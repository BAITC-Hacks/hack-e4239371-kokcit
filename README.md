# WindFlow AI

Agentic AI-система для почасового прогнозирования нормализованной выработки двух
ветровых турбин на горизонте 24–48 часов. Проект разработан для кейса HackAlem AI
2026 «Agentic AI для прогнозирования выработки ВЭС».

## Что умеет прототип

- получает архивные прогнозы погоды по координатам турбин из Open-Meteo Previous Runs API;
- использует только прогноз, доступный на дату расчёта, без подглядывания в будущую фактическую погоду;
- строит 24- и 48-часовой прогноз мощности отдельной моделью для каждой турбины и горизонта;
- автоматически выполняет полный агентный цикл: получение данных, валидация, признаки, расчёт, контроль качества и сохранение;
- воспроизводит 28 ежедневных запусков за февраль 2026 года и формирует 672 почасовых значения;
- сохраняет историю в SQLite, показывает график и таблицу, экспортирует одиночный или месячный прогноз в CSV.

## Архитектура

```text
Open-Meteo Previous Runs API
             |
             v
  Weather loader + validation
             |
             v
 Feature pipeline (wind, direction, temperature, calendar)
             |
             v
 HistGradientBoosting models (2 turbines x 2 horizons)
             |
             v
 Quality checks -> SQLite -> FastAPI -> React dashboard / CSV
```

`backend/app/agent.py` управляет шагами процесса. Для прогноза первого дня
используются поля `previous_day1`, для второго — `previous_day2`. Таким образом,
при расчёте от 31 января прогноз на 1–2 февраля соответствует данным, которые могли
быть доступны именно 31 января.

## Стек

- Python 3.12, FastAPI, pandas, scikit-learn, joblib, SQLite;
- `uv` для зависимостей Python и воспроизводимого `uv.lock`;
- React, Vite, Recharts и Lucide для интерфейса;
- Open-Meteo Previous Runs API как открытый источник архивных прогнозов.

## Быстрый запуск

Требуются Python 3.12+, [uv](https://docs.astral.sh/uv/) и Node.js 20+.
Секреты и API-ключи для запуска не нужны.

Терминал 1:

```powershell
cd backend
uv sync --locked
uv run uvicorn app.main:app --reload
```

Терминал 2:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Документация API доступна на
`http://localhost:8000/docs`. Vite перенаправляет запросы `/api` на backend.

## Демонстрационный сценарий

1. Выберите турбину и горизонт 24 или 48 часов.
2. Для первого тестового расчёта укажите дату выпуска `2026-01-31`.
3. Нажмите «Рассчитать прогноз» и покажите график, журнал агента и почасовую таблицу.
4. Нажмите «Весь февраль 2026»: агент выполнит 28 последовательных дневных расчётов.
5. Скачайте CSV с 672 строками прогноза кнопкой в правой части графика.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Проверка backend |
| `GET` | `/api/models/metrics` | Метрики обученных моделей |
| `POST` | `/api/forecasts` | Прогноз на 24 или 48 часов |
| `POST` | `/api/forecasts/february?turbine_id=1` | Все 28 запусков февраля |
| `GET` | `/api/forecasts` | История расчётов |
| `GET` | `/api/forecasts/{run_id}` | Сохранённый расчёт |
| `GET` | `/api/forecasts/{run_id}/export.csv` | CSV одного расчёта |
| `GET` | `/api/forecasts/february/export.csv?turbine_id=1` | CSV за февраль |

Пример запроса:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/forecasts `
  -ContentType application/json `
  -Body '{"turbine_id":1,"issue_date":"2026-01-31","horizon_hours":48}'
```

## Модель и качество

Десятиминутные данные турбин агрегируются до почасовых средних. Признаки включают
скорость ветра на 10 и 100 м, квадрат и куб скорости, направление ветра через
`sin/cos`, температуру, час суток и день года. Для каждой пары «турбина + день
горизонта» выбирается лучший профиль `HistGradientBoostingRegressor` или
`ExtraTreesRegressor` по MAE на хронологической валидации за январь 2026 года.

| Модель | MAE | RMSE | R² |
| --- | ---: | ---: | ---: |
| Турбина 1, день 1 | 0.163 | 0.218 | 0.581 |
| Турбина 1, день 2 | 0.196 | 0.258 | 0.414 |
| Турбина 2, день 1 | 0.165 | 0.223 | 0.563 |
| Турбина 2, день 2 | 0.198 | 0.254 | 0.434 |

Целевая мощность нормализована от 0 до 1. Обученные модели и
`backend/models/metrics.json` включены в проект, поэтому переобучение для проверки
интерфейса не требуется.

## Переобучение

Исходные CSV не публикуются в репозитории. Если они доступны локально:

```powershell
cd backend
uv run python -m scripts.train_baseline `
  --turbine-1 "C:\path\to\turbine 1.csv" `
  --turbine-2 "C:\path\to\turbine 2.csv"
```

Архивная погода кэшируется в `backend/data_cache/`, модели сохраняются в
`backend/models/`. Локальные данные, база SQLite и файлы окружения исключены из Git.

## Ограничения и развитие

Текущая версия прогнозирует нормализованную, а не физическую мощность в МВт,
поскольку номинал турбин в данных не указан. Следующие улучшения: временной
backtesting по нескольким месяцам, признаки лагов фактической мощности, ансамбль
моделей, мониторинг дрейфа и планировщик ежедневного автоматического запуска.
