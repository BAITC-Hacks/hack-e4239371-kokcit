# WindFlow AI

Почасовой прогноз нормализованной мощности двух ветротурбин на следующие
24–48 часов. FastAPI + React, обученные ML-модели, проверка на январе 2026,
журнал агента, SQLite и полный февральский экспорт.

## Запуск у судей

Секреты, API-ключи и личные аккаунты команды не нужны. Модели и январский
архив прогнозов погоды включены в репозиторий. После установки зависимостей
январское демо работает без интернета и действительно выполняет модель.

### Windows: одна команда

Требуются Python 3.11+, [uv](https://docs.astral.sh/uv/) и Node.js 22.12+.

```powershell
.\run.ps1
```

Открыть **http://127.0.0.1:8000**. Один сервер обслуживает API и собранный сайт.
Остановить: Ctrl+C. Повторный запуск без установки: `./run.ps1 -SkipInstall`.
Проверка тестов и сборки: `./run.ps1 -SkipInstall -Check`.

### Docker (Windows / Linux / macOS)

Требуется запущенный Docker Engine / Docker Desktop.

```sh
docker compose up --build
```

Открыть **http://localhost:8000**. Данные сохраняются в именованном томе.
Конфигурация Compose проверена; сборка и запуск контейнера в среде разработки
не проверены, поскольку Docker daemon не запущен.

### Вручную / режим разработки

```sh
cd backend
uv sync --locked
uv run uvicorn app.main:app --reload
```

Во втором терминале:

```sh
cd frontend
npm ci
npm run dev
```

Сайт: http://localhost:5173, API: http://localhost:8000/docs.
Для единого сервера сначала выполните `npm run build` в frontend, затем
запустите backend; собранный сайт доступен на порту 8000.

## Демонстрация за 2 минуты

1. Оставьте дату выпуска **29.01.2026**, выберите турбину и горизонт 48 часов.
2. Выберите «Только сохранённый архив» и нажмите «Рассчитать прогноз».
3. Покажите реальные шаги агента, 48 значений на 30–31 января, график и CSV.
4. Откройте «Проверка качества»: факт/прогноз для 720–744 часов января,
   MAE/RMSE/R² и сравнение с предыдущей версией и простыми методами.
5. Выберите вторую турбину и повторите расчёт; откройте его из истории.

Дата выпуска означает конец дня в UTC+5. Для январского демо автоматически
используется отдельная модель, обученная только до 1 января.

## Весь февраль и файлы сдачи

Кнопка «Февраль · 28 × 24 часа» выполняет выпуски с 31 января по 27 февраля
и выдаёт 672 уникальных часа на турбину. Для этого нужен интернет либо
заранее сохранённая **погода** февраля. В текущем комплекте сохранён январь;
старые результаты февраля из локальной SQLite не заменяют архив погоды.

Один раз на компьютере с доступом к Open-Meteo:

```sh
cd backend
uv run python -m scripts.prepare_demo
```

Команда сохраняет реальную погоду января и февраля в `backend/demo/` и
манифест происхождения с SHA-256. После этого весь февраль считается офлайн.

Подготовка обоих CSV и отчёта для сдачи:

```sh
uv run python -m scripts.export_submission --offline
```

Результаты: `artifacts/submission/`, по 672 строки для каждой турбины,
`manifest.json` и `metrics.json`. Неполный месяц не экспортируется.
Фактическая февральская выработка в исходных данных отсутствует,
поэтому качество на феврале пока не измерено.

## Качество модели

Параметры выбираются по **декабрю 2025**, затем модель обучается на данных
до января и проверяется на **январе 2026**. Первый день оценивается на 744 часах,
второй — на 720 часах со 2 января, поскольку его выпуск должен находиться после
границы обучения. Рабочая февральская модель после проверки переобучается с
добавлением января.

| Турбина и часть прогноза | Часов | MAE | RMSE | R² | Снижение MAE к wind curve |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1, первые 24 часа | 744 | 0.147 | 0.202 | 0.641 | 17.15% |
| 1, второй день (25–48 ч) | 720 | 0.191 | 0.246 | 0.466 | 5.23% |
| 2, первые 24 часа | 744 | 0.152 | 0.207 | 0.624 | 15.02% |
| 2, второй день (25–48 ч) | 720 | 0.188 | 0.243 | 0.478 | 6.62% |

**Цель R² ≥ 0.80 пока не достигнута.** R² не является процентом точности.
MAE измеряется в шкале мощности 0–1. Новые признаки описывают изменение
прогнозируемой погоды внутри суток; сравниваются HistGradientBoosting,
ExtraTrees и их ансамбли. Будущие фактические показания турбин не используются.

Доказательства и воспроизводимость:

- `backend/models/metrics.json` — метрики, периоды, методы сравнения, хеши данных;
- `backend/models/model_selection.json` — сравнение настроек по декабрю;
- `backend/models/validation_predictions.csv` — 2 928 проверочных строк: по 744
  для первого дня и по 720 для второго дня каждой турбины;
- `backend/models/validation/` — модели до января;
- `backend/models/*.joblib` — модели для февраля.

Январские результаты предыдущей версии уже были известны при разработке;
это проверочный период, а не новый полностью скрытый тест.
Подробности: [протокол прогноза и оценки](docs/FORECAST_PROTOCOL.md).

## Архитектура

```text
React dashboard ── POST /api/jobs ── фоновые задания (один процесс API)
                                          │
                                     Агент состояний
                                          │
                    Погода → Проверка часов → Признаки → ML
                                          │
                          Контроль результата → SQLite
                                          │
                       Журнал + графики + история + CSV

CLI / ежедневный планировщик ───────── тот же агент
```

Агент фиксирует начало, завершение и длительность шагов, показывает
повторные запросы и причину ошибки. Ошибка погодного сервиса возвращает
понятный ответ 503. Проверяются дубликаты, пропуски, нечисловые значения,
диапазон мощности и полнота месячного экспорта.

Оркестратор детерминированный; LLM не используется. Для локального прототипа
достаточно одного процесса Uvicorn. Успешные журналы сохраняются в SQLite;
фоновые задания и журналы их ошибок хранятся в памяти до перезапуска.

## Время прогноза: существенное ограничение

Open-Meteo Previous Runs предоставляет прогнозы с фиксированным
упреждением 24/48 часов. Это не единый метеорологический выпуск
с фиксированным временем инициализации. Фактическая будущая погода не
используется, но точная доступность каждого архивного значения к минуте
запуска не доказана: API не сообщает время публикации.

Если критерии требуют строгий запуск «на определённый час», нужен
Single Runs API с фиксированным `run`, учётом публикации и повторной
валидацией на том же источнике. См. [документацию источника](https://open-meteo.com/en/docs/previous-runs-api)
и [протокол](docs/FORECAST_PROTOCOL.md).

## Ежедневный запуск

Один расчёт обеих турбин на 48 часов:

```sh
cd backend
uv run python -m scripts.run_daily --issue-date 2026-01-29 --offline
```

Ежедневно в 23:59:59 UTC+5, пока процесс работает:

```sh
uv run python -m scripts.run_daily --loop
```

Или отдельный сервис Docker: `docker compose --profile schedule up --build`.
Без даты и без `--loop` CLI использует последний завершённый день.
Для реальной ежедневной работы требуется доступ к погодному API.
Прогнозы дат позже периода проверки являются экстраполяцией;
ежедневное переобучение и автоматический контроль дрейфа не реализованы.

## Переобучение

Исходные CSV участников не включены целиком. Укажите их пути:

```powershell
cd backend
uv run python -m scripts.train_models --turbine-1 "C:\data\turbine 1.csv" --turbine-2 "C:\data\turbine 2.csv"
```

При первом обучении нужен доступ к погодному API для истории;
скачанная история сохраняется в `backend/data_cache/`.
Повторное обучение с сохранённым выбором параметров:
добавьте `--selection-report models/model_selection.json`.

Для последовательного вычисления на ограниченных Windows-средах можно
установить `$env:OMP_NUM_THREADS = '1'`.
`scripts/train_baseline.py` сохранён как исходный baseline; он обучает
предыдущую версию и не должен перезаписывать актуальную папку models.
При его использовании передайте другую папку `--model-dir`.

## Проверки

### Дополнительное сравнение на GPU

В текущих моделях scikit-learn обучение выполняется на CPU. Для отдельного
эксперимента на NVIDIA GPU подготовлен CatBoost-скрипт. CatBoost не входит
в зависимости приложения; его установка и GPU-обучение в текущей среде
не выполнены из-за отсутствия доступа к PyPI.

На Windows с доступом к сети, из папки backend:

```powershell
uv pip install --python .venv\Scripts\python.exe catboost
.\.venv\Scripts\python.exe -m scripts.benchmark_gpu --data-dir "$env:USERPROFILE\Downloads"
```

Он явно использует `task_type="GPU"`, выбирает настройки по декабрю и
сохраняет январское сравнение в `backend/data_cache/gpu/comparison.json`.
Рабочие модели приложения автоматически не перезаписываются.
GPU ускоряет поддерживаемые операции, но не гарантирует R² ≥ 0.80.
У GPU CatBoost возможны небольшие различия между повторными запусками:
[официальная документация](https://catboost.ai/docs/en/features/training-on-gpu).

### Проверка приложения

```sh
cd backend
uv run ruff check .
uv run pytest -q
cd ../frontend
npm run build
```

Тесты выполняют реальные модели на сохранённой январской погоде, сверяют
предсказания с отчётом, пересчитывают метрики, проверяют ошибки, журнал,
идемпотентность и полноту CSV. Для теста календарного февральского пакета
используется явно синтетическая погодная фикстура; это проверка программы,
не свидетельство точности модели на феврале.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/health | Состояние и наличие моделей |
| GET | /api/models/metrics | Метрики и протокол обучения |
| GET | /api/models/validation?turbine_id=1&lead_days=1 | Все факты и прогнозы января |
| POST | /api/jobs | Фоновый прогноз 24/48 часов |
| POST | /api/jobs/february | Фоновый февральский пакет |
| GET | /api/jobs/{job_id} | Прогресс, шаги, ошибка, результат |
| POST | /api/forecasts | Синхронный прогноз |
| POST | /api/forecasts/february?turbine_id=1 | Синхронный февральский пакет |
| GET | /api/forecasts | История |
| GET | /api/forecasts/{run_id} | Прогноз и сохранённый журнал |
| GET | /api/forecasts/{run_id}/export.csv | CSV прогноза |
| GET | /api/forecasts/february/export.csv?turbine_id=1 | Полный CSV февраля |

Тело запроса прогноза:

```json
{"turbine_id":1,"issue_date":"2026-01-29","horizon_hours":48,"data_mode":"offline"}
```

Режимы: `auto` (сначала сохранённый архив, затем сеть), `offline`, `live`.
Настройки через переменные окружения: `MODEL_DIR`, `DATABASE_PATH`,
`DEMO_DIR`, `WEATHER_CACHE_DIR`, `WEATHER_TIMEOUT_SECONDS`, `WEATHER_ATTEMPTS`.
Файл `.env` необязателен.
